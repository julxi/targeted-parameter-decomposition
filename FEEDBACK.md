# FEEDBACK

A list of problems with the documentation or workflow, noted by agents (or humans), each with constructive criticism on how it could have been prevented. This is how the conventions improve instead of rotting: when an agent makes a mistake that better instructions would have prevented, the mistake gets an entry here, and a periodic review turns recurring entries into new rules.

Entry format: date, what went wrong (or what friction occurred), and — where possible — a concrete suggestion: which file should say what, so the next agent doesn't hit the same problem.

That kept readers being sent to documents being phased out; Julian caught it. - 26-10-06 — `spd-vast` called `vastai destroy instance <id>` with captured output and no `-y`. vastai 1.2.0 asks for confirmation unless it gets `-y`; the prompt was invisible and the launcher hung after blacklisting a host, while the instance kept billing. `--destroy_on_exit` had the same latent bug, so it had probably never worked. - 26-10-13 — Two near-misses with numbers at float-noise level, both from the tiny random Qwen2 used for CPU smoke tests. (1) The agent printed metrics with `awk '{print substr($2,1,8)}'`, which cut `-7.6137e-08` to `-7.61374`, and briefly took a correct smoke run for a bug (negative KL of -7.6). (2) A new unit test compared a lens loss with a hand-computed KL using `assert_close`'s default tolerances, but the tiny model's logits have std ~0.01, so all KLs were ~1e-7 to 1e-6 and below `atol=1e-5`; a mutation check failed only by a hair. Fix used: scale the tiny model's final norm by 1000 in the test (logits std ~10) and assert that the tested quantity is far above noise. Prevention, for `docs/CODING.md` (Logging & Observability or Tests): "Never truncate printed numbers by character count; use a format such as `%.4g`. In tests on tiny random models, first assert that the compared quantity is well above float noise, and pass explicit tolerances."

- 26-10-15 — A 57-minute steering sweep on a rented 4090 (`~/spd_out/26-10-10_bolder_experiments/steering_sf/steer_sf.py`; `convos/julian/26-10-10_bolder_experiments_LOG.md`, entry *prompt chosen: the amount question on a new line*) crashed on its final sanity check and lost all results, because the script saved them only after the check. - 26-10-16 — The causal layer scan (`~/spd_out/26-10-10_bolder_experiments/layer_scan/`; `convos/julian/26-10-10_bolder_experiments_LOG.md`, entry *causal layer scan*) replaced each MLP output by its mean over statement tokens, pooled into three position groups. In Qwen2.5-7B a few tokens per statement have MLP outputs of norm up to ~11,600 at layers 3, 4 and 26 (median ~10–240; the "massive activations"). The pooled means were therefore dominated by them (norm 815 vs median 9.5 at layer 3), and mean ablation wrote a massive vector at every token: three layers looked essential or format-breaking, and only the zero-ablation reference showed it was an artifact. The same tokens had already broken the group reflection in the steering run the day before (entry *statement-first steering run: results*). Prevention: before averaging activations over positions in this model (mean ablation, group directions, group midpoints), compare the norm of the mean with the median per-token norm, and exclude or separately average the massive tokens. A one-line note in `docs/CODING.md` would carry this to future scripts.
